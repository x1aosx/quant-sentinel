# Codex 实施指令：先量化策略内核，再策略管理网站

> 将整个交付目录放到项目 `docs/strategy_v2/`。  
> 本文件规定执行顺序；交易细节以 `02_SRPA_STRATEGY_SPEC.md` 为准；产品/架构以 `03_STRATEGY_PLATFORM_DESIGN.md` 为准；上游来源与审查以 `01_SOURCE_AUDIT.md` 为准。  
> 本交付是设计与策略规格，不包含已经实现的引擎。下列 CLI 为要求实现的目标命令，不应向用户声称现在已经存在。

## 1. 可直接发送给 Codex 的启动指令

```text
你正在开发 X-Quant：本地、策略优先的量化研究与策略管理系统。

先完整阅读 docs/strategy_v2/ 下的 01_SOURCE_AUDIT.md、
02_SRPA_STRATEGY_SPEC.md、03_STRATEGY_PLATFORM_DESIGN.md 和本文件，
以及 configs 下两个 YAML。旧 X-Stock 设计中“先网站后策略”的顺序已被替代。

本轮目标是 P0+P1：实现可测试的量化内核与本地回放最小闭环。
不要先搭建大型网页、新闻模块或 LLM 多代理；不要只生成接口空壳。

先检查现有仓库，保留已有可复用代码、数据与用户修改，不进行破坏性重建。
建立 docs/strategy_v2/IMPLEMENTATION_STATUS.md，逐项列出已完成、未完成和阻塞项。

1. 固定两个用户指定上游仓库的真实 commit SHA，审查列出的关键路径、许可与差异。
   无法访问源时标记 SOURCE_PIN_PENDING；继续独立实现合成数据可验证内核，
   但不复制未知许可代码、不伪造 SHA、不声称上游已复现。
2. 实现严格时间切片、市场日历接口、OHLC 校验、EMA/ATR/RS、确认枢轴、SR 区域。
3. 实现 S-BR 的有限状态机、入场/失效/退出、计划有效期、风险数量与现金预留。
4. 实现 B-CASH、B-EMA、B-DC 基线与共用的下一会话参考执行/账本。
5. 使用合成夹具建立必经测试，特别是未来数据、同棒交易、H2 计数、
   成本/数量、跳空不成交、重复事件和恢复后不得重复计划。
6. 实现 CLI 导入/校验本地行情、校验策略配置、运行回放、导出报告。
7. 测试与报告必须真实生成；合成数据显著标 DEMO，不能伪造真实策略收益。

量化策略代码必须独立于 FastAPI/React/外部行情库，研究模式禁止联网，
真实成交只能由 execution import 进入真实账本。
core 使用 Python，默认本地 SQLite+Parquet，不预设必须有 Redis 或云数据库。
不要一次引入多个完整回测框架。

完成后提供：修改文件、可复现命令、真实测试结果、合成回放工件位置、
关键设计决定、未完成的收益验证/数据/许可事项。
未经明确审批不得启用 live_assist，更不得自动券商下单。
```

依赖锁文件必须由实际解析生成，不能手写虚假包哈希。Python/Node 版本取实际依赖兼容集合后固定，不在代码中自动跟随 latest。运行路径支持 Windows/macOS/Linux 的普通本地目录，不继承上游个人 Windows 路径。

## 3. P0：把策略和数据边界固定下来

交付 `sources.lock.json`、来源审查结果、输入 schema、策略 manifest/schema、核心领域类型、模拟市场规则/费用夹具与合成行情生成器。对本项目自写代码和上游适配代码做明确区分。

`sources.lock.json` 中真实 SHA 未取得则必须为 null 且状态 pending；不准用日期、分支名或随机哈希代替。已固定后保存关键源文件哈希、许可、抓取时间、检查文件列表。上游下载目录只读，不自动安装/执行。

数据契约必须包含 `available_at`；市场规则至少有 tick、买入数量规则、卖出可用时间、交易时段、价格限制、费用与生效日期。示例市场规则只能用于 DEMO，不宣称代表所有 A 股板块或当前真实费率。

**P0 验收**：配置无法通过未定义字段、非法参数、错误时间顺序；价格低于零、OHLC 不一致、重复会话和股票池缺关键数据能被明确识别。缺少正式规则/费用配置不阻塞合成研究，但阻止正式部署。

## 4. P1：交付首个能运行的策略内核

实现 xq_sr_v01、状态分类、S-BR、共同风险与 EOD 回放、B-CASH/B-EMA/B-DC。公开接口实现后必须有实际算法，禁止以 return [] 之类占位代码通过演示。

状态、事件、计划和账户写入路径只允许 Coordinator 提交。策略计算不读取系统当前时刻、不联网、不发通知、不写真实账本。Context 必须包含事件类型、只读市场切片、状态、实际/仿真持仓视图，并能处理填单/取消/公司行为对状态的影响。

最少设计四组合成行情：有效突破回测、突破后立即失败、仅影线触及不确认、确认后次一会话跳空越界。至少有一组真实走完生成计划→参考成交→退出→成本→权益变化，预期事件日期和数值必须由独立手算/小样本推导断言。

目标命令示例：

```bash
uv sync --locked
uv run pytest tests/unit tests/property tests/integration -q
uv run xquant data validate --input tests/fixtures/synthetic/valid_case.parquet --mode demo
uv run xquant strategy validate --config configs/demo/srpa_demo.yaml
uv run xquant replay --config configs/demo/srpa_demo.yaml --output artifacts/demo/srpa
uv run xquant experiment compare --runs artifacts/demo/srpa artifacts/demo/donchian
```

CLI 应优先实现 clear errors、非零失败退出码与 JSON 日志，不要求固定依赖某个 Make 工具。回放报告中模拟曲线、样本数量和缺乏真实验证必须直接可见。

**P1 验收**：不启动网页、不提供任何外部密钥，也能完整运行；同一输入在固定环境重跑得到一致事件和成交结果；没有真实数据时不生成“真实回测优于基准”的结论。

## 5. P2：把研究做成可复现的策略管理能力

实现策略目录、版本冻结、参数 schema、实验记录、批量回放、基线比较、逐层过滤漏斗、时间外切分/purge、标签成熟、成本与跳空压力测试，以及报告导出。数据接入至少支持本地 CSV/Parquet 与一个实际取得权限的行情 Provider；权限未取得时保留 pending，不捏造接口成功。

研究脚本必须复用策略引擎，不能另写一套简化收益曲线把风控、停牌和未成交删掉。保存所有实验尝试与失败原因；参数搜索预算≤24 组作为首轮默认。先验证主策略规则层，不要求在此阶段引入 LightGBM。

**P2 验收**：实验可以从指纹定位到数据、规则、版本和执行模型；改变后续行情不改变之前特征/信号；同日不同证券不跨训练/验证分割；窗口未完整结束的标签不进入训练。缺少授权历史/点时信息时只能标记研究受限，不允许自动晋级 OOS_PASSED。

## 6. P3：完成本地策略管理网站与仿真闭环

此时才实现网页。页面必须读取真实注册表/实验/计划 API，不在前端写策略公式。实现策略卡片、参数/版本 diff、回测记录、K 线逐棒回放、实例绑定/启停、持仓/风险、候选雷达、数据健康和通知反馈。

实现 `paper` 运行、策略计划 outbox、一个真实配置的外部通知渠道、实际成交 CSV 导入与幂等对账。程序退出/休眠恢复不得发送过期买入；暂停新增必须继续持仓风险监控。删除或回滚版本不得导致已有 lot 无退出政策。

**P3 验收**：用户能在浏览器创建/复制策略版本、启动一次回放、查看失败原因、绑定仿真实例、收到正确标识的消息、确认/忽略、导入成交并查看复盘。该闭环与 CLI 使用同一服务层。

## 7. P4：增加预测与更多策略，而不是先上 AI

实现 P-TOUCH、P-REACT（包含 timeout）、P-TRADE 的标签与模型注册；先发生率/逻辑回归，再做 LightGBM 挑战者。加入 H2 与偏多区间独立策略、动量基线、Boll/CCI 挑战者、模型校准/漂移、Champion/Challenger 和归因。

LLM 仅允许解释与研究假设，必须标为旁路，不得调用账户写接口、不修改硬风控、不得把未经统计评估的百分比发成获利概率。

**P4 验收**：模型缺失/特征版本错配/标签版本变化时拒绝统计过滤；同一股票上的概率必须注明目标、时点、样本与校准版本；概率指标提升与交易收益提升分别报告。

## 8. P5：批准人工实战辅助，保留证据闭环

落实版本审批、用户风险限额、实际可执行计划对照、通知延迟/休眠空窗验证、备份恢复、压力情景和紧急暂停。只有满足规则书门槛的精确版本才可进入 `live_assist`。

未通过收益/执行证据时，交付“功能可用但策略未达资金部署条件”的系统，不要求 Codex 为通过验收编造赚钱曲线。自动券商交易不是本阶段的隐含任务。

## 9. 必经验收测试

| ID | 测试 | 必须观察到的结果 |
|---|---|---|
| T01 | 行情前缀计算与完整序列按时点计算 | 同一时点特征、区域、状态与信号一致 |
| T02 | 任意替换 t 之后行情 | t 及以前特征/信号不变；未来标签可以变化 |
| T03 | 分形枢轴确认 | i+2 完成前不能使用 i 的枢轴 |
| T04 | 区域冻结后追加新高低点 | 旧计划的区域 ID/边界不被重新画图覆盖 |
| T05 | 成交量分配 | 各箱总量等于输入衰减量，含零幅棒 |
| T06 | H2 两腿计数 | 连续上涨或同一回撤不冒充 H2；每腿可定位 |
| T07 | S-BR 阶段顺序 | 突破当棒不能完成整个状态机并成交 |
| T08 | 次一会话入场 | s 收盘信号的参考成交时间严格晚于 s |
| T09 | 下一会话跳空超上限/低于有效区 | 取消计划，不调宽入场区间 |
| T10 | EOD 盘中穿目标/保护阈值但收盘未穿 | 不记为已止盈/止损；记录日内风险观察 |
| T11 | 跟踪阈值顺序 | 先用旧阈值判断，再计算下个会话的阈值 |
| T12 | T+1/卖出数量限制夹具 | 不允许出售尚不可卖数量，不虚构保护成交 |
| T13 | 停牌/开盘限制价缺排队信息 | 保守不成交，留下原因而不是删除交易 |
| T14 | 最低佣金和小单 | 整手规范化后重新计费，超预算时减量或拒绝 |
| T15 | 多个实例同时触发 | 账户预算只被分配一次，退出优先，确定性排序 |
| T16 | 同股多策略冲突 | 不叠加重复仓位；保留次要命中依据 |
| T17 | 未分配手工仓位 | 占用风险/现金/行业敞口，历史收益不归新策略 |
| T18 | 重复导入同一成交 | 账本与持仓只更新一次 |
| T19 | 通知成功/用户确认但无成交 | 真实仓位保持不变 |
| T20 | 重复事件、任务重试、事务后应答丢失 | 无重复计划/资金预留/成交 |
| T21 | 休眠后补齐 5 天行情 | 旧买入计划过期；退出风险按当前状态重建 |
| T22 | 暂停新增/回滚 | 已有仓位仍有风险监控，原版本血缘保持 |
| T23 | 未来 40+10 会话窗口未成熟 | 标 censored，不计 no_touch 或 timeout |
| T24 | 反应标签未决 | 成熟 timeout 进入条件分布，不被偷偷丢弃 |
| T25 | 区域无预测输出 | 几何召回计入漏检，不能提高评分 |
| T26 | 多标的时间切分与 purge | 同日不跨组，重叠标签区间被清除 |
| T27 | 测试集访问审计 | 调参后不能仍标同一保留段未被查看 |
| T28 | 模型特征顺序/版本/频率错配 | 拒绝推断，不仅打印 warning 继续交易 |
| T29 | `p_stall` / SR 分数 | 不作为百分比或交易获利概率展示 |
| T30 | 缺关键测试数据 | skip 单独显示，不计作通过，不允许晋级 |
| T31 | 配置缺市场/费用/基准/风险审批 | research demo 可单独运行，live_assist 不可启动 |
| T32 | Python 策略试图联网/读密钥 | 核心内置约束检测阻止；不信任代码不进入首版运行 |
| T33 | 拆股与现金分红 | 账本数量/现金和价格尺度一致，无虚假突破/收益 |
| T34 | 交易所日历与时区 | 午休/假期/未结束周线不生成错误会话数据 |
| T35 | 备份恢复 | 能恢复同一版本、账本、未结计划与所引用工件 |
| T36 | 没有符合条件的交易 | 正常输出零计划和过滤漏斗，不报成功买入或强行造信号 |

T32 中“子进程”不代表安全沙箱。应先拒绝不信任插件进入执行，后续沙箱能力必须有 OS 级测试，不能仅通过 monkeypatch socket 就宣称隔离完成。

## 10. 每阶段报告格式

每阶段提交 `IMPLEMENTATION_STATUS.md`，分别列出实现功能、实际运行命令、通过/失败/跳过测试、生成的工件、真实数据覆盖、尚未验证事项、下一阶段依赖。任何实际测得的性能/收益必须附 run_id 与数据/参数指纹。

代码评审至少覆盖：时点与价格尺度、指标初始化、标签定义、真实可成交性、费率/数量、预算竞争、状态恢复、版本不可变与许可。网页截图不是量化逻辑验收材料。

## 11. 不允许的完成方式

禁止只搭建前端卡片；禁止把全部开源策略装进来却没有统一接口；禁止使用未来高低点后再给历史入场；禁止忽略不能成交样本；禁止回测用日内止损而实际只有收盘提醒；禁止把“模型产生了概率”当作“模型通过验证”；禁止用真实账户风险承受能力未知的默认值直接部署。

目标不是策略数量最多，而是**每个纳入的策略都能解释、重跑、比较、管理、停止、回滚，并在真实约束下接受检验**。
